This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Project P4O** is a Godot 4.6 game combining hex-grid tactical battles with visual novel/dating sim elements, written in GDScript. The renderer is GL Compatibility.

There is no build system or test framework — the project is run and tested through the Godot editor. Open the project in Godot 4.6+ and press F5 (or the play button).

## Architecture

### Game State Machine (Autoload: `Game`)

The `Game` autoload (`src/autoloads/game.gd`) is the central scene manager. It owns the lifecycle of 6 major states, switching between them by clearing children and instantiating the corresponding scene:

- **main_menu** — Title screen
- **place** — Hub area for character (datable) interactions
- **story** — Visual novel engine with streaming text, choices, backgrounds, and embedded stage battles
- **stage** — Hex-grid tactical battle (the core gameplay)
- **travel** — Destination selection menu
- **explore** — Mission/stage selection (placeholder)

Call `Game.change_state("state_name")` to transition. The Game singleton holds references like `Game.stage`, `Game.story`, etc. for cross-system access.

### Other Autoloads

- **SaveManager** — Save/load via `.tres` Resource files in `user://saves/`. Holds `current_save: SaveData`.
- **Config** — Development flags (e.g. `debug_skip_story`).
- **Notification** — Toast notification system. Call `Notification.notify(NotificationData.new())`.

### Stage (Battle) System

The most complex subsystem. Key nodes are exported on the Stage scene and coordinated by `StageState`:

- **StageState** (`src/game/stage/state.gd`) — Battle coordinator. Manages phases (`preparation` → `playing` → `completed`), tile selection, overlay computation, and turn flow.
- **StageUnit** (`src/game/stage/unit.gd`) — Unit registry. Maintains `at: Dictionary[Vector2i, Unit]` spatial hash. Handles spawn/despawn and recomputes movement/action ranges.
- **Map** (`src/game/stage/map.gd`) — TileMapLayer that handles all stage mouse input (click to select/move/attack, hover for spawn preview).
- **Spawner** (`src/game/stage/spawner/spawner.gd`) — UI for placing player units during preparation phase.
- **Overlay** (`src/game/stage/overlay.gd`) — Static singleton for tile highlighting with a stack-based state system (MOVE_REACHABLE, ATTACKABLE, etc.).
- **Camera** (`src/game/stage/camera.gd`) — WASD/HJKL movement with zoom.

### Unit Component System

Units (`src/game/stage/units/unit.gd`) use component composition:

- **Movement** — Flood-fill reachable tile computation, A\* pathfinding with tween animation.
- **Health** — HP tracking, damage, death.
- **Actions** — Child nodes under an "Actions" container. Base class `Action` has abstract `perform(target)` and `compute_actionable_tiles()`. `AttackAction` extends with attack_type/element.

Components reference their parent unit via `@onready var unit = get_parent()`.

### Story System

The story engine (`src/game/story/story.gd`) processes `Array[StoryEntry]` sequentially using async/await. Entry types:

- **DialogueStoryEntry** — Character name + streaming text
- **BackgroundStoryEntry** — Scene background change
- **ChoiceStoryEntry** — Branching choices
- **StageStoryEntry** — Embeds a full tactical battle mid-story

Story can also appear mid-battle via the wave hook system (`StoryHook`).

### Resource / Data Layer

Content is data-driven using Godot Resources (`.tres` files in `data/`):

- **StageResource** → waves (`StageWave`) → spawn entries + hook entries
- **StoryResource** → array of `StoryEntry` subtypes
- **SaveData** — day, time (0-23), route, owned datables
- **Datable** — Character with level/points progression (100 + level\*100 per level-up)

### Hex Grid

Uses offset coordinates with row-parity handling. Key utility: `src/utils/hex_utils.gd` — `tile_to_px()`, `get_adjacent_hex()`. Tile size is `Vector2i(110, 128)`. Tile properties (movement cost) defined in `src/utils/constants.gd`.

## Editing Rules

- **Only write `.gd` files.** Never directly edit `.tscn` (scene) or `.tres` (resource) files. These are managed by the Godot editor. If a change requires modifying a `.tscn` or `.tres` file, describe the desired change to the user so they can make it in the editor.

## Key Conventions

- Enums are centralized in `src/utils/enums.gd` (AttackType, Element, OverlayState).
- Constants/lookup tables live in `src/utils/constants.gd` (UNITS_TABLE, TILES).
- Input actions are defined in `project.godot` — movement uses both WASD and HJKL (vim-style).
- The stage dynamically loads map scenes from `data/maps/` at runtime via `StageResource.map`.
- Unit scenes live under `src/game/stage/units/` organized by type (pieces, structures).
- Action scenes are nested under `src/game/stage/actions/` by category (attack/melee/sharp/...).

### Autoloads — Full API

| Autoload       | File                                         | Key API                                                                                                             |
| -------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `Game`         | `src/autoloads/game.gd`                      | `change_state(States)`, `stage`, `story`, `place`, `explore` — live refs                                            |
| `SaveManager`  | `src/autoloads/save_manager.gd`              | `new_save()`, `save(slot)`, `load(slot)`, `delete(slot)`, `has_save(slot)`, `get_saves()`, `current_save: SaveData` |

| `Notification` | `src/autoloads/notification/notification.gd` | `notify(NotificationData)` — auto-removes after 4 s                                                                 |
| `SigBus`       | `src/autoloads/sig_bus.gd`                   | `signal toggle_pause_menu`                                                                                          |

`Game.States` enum values: `MAIN_MENU=0`, `STORY=1`, `STAGE=2`, `PLACE=3`, `TRAVEL=4`, `EXPLORE=5`.

### Game Flow (Scene Transitions)

```
Launch → MainMenu
  New Game → SaveManager.new_save() → PLACE
  Load Game → SaveManager.load("slot0") → PLACE
PLACE → TRAVEL → EXPLORE → STAGE
STAGE (all objectives met) → StageSummary → PLACE
Escape (any state) → PauseMenu overlay (CanvasLayer) → save/load → PLACE
```

### Stage System — Detailed

**Initialization** (`Stage.start(data: StageResource)`):

1. `spawner.setup()` — populates spawn buttons
2. `data.map.instantiate()` → added to scene tree
3. `objective.setup(data.objectives)` — connects `all_objectives_completed` + `objective_completed`
4. `_spawn_wave(data.initial_wave)` — spawns initial units

**Phase machine** (`StageState.state: String`):

- `"preparation"` → End Preparation button shown; player places units
- `"playing"` → End Turn button shown; main combat
- `"completed"` → `StageSummary.visible = true`

**Turn flow** (`StageState.end_player_turn()`):

1. Deselect tile
2. Increment `current_turn`
3. Call `unit.on_turn_end()` for all PLAYER units (restore movement + uses, recompute)
4. Check all objectives

**Mouse input flow** (all in `StageMap._unhandled_input`):

- Playing + selected + player unit → move or act or deselect
- Playing + no selection → `state.select_tile(cell)`
- Preparation + spawner unit selected → spawn ghost/place unit
- Mouse motion → spawn preview ghost

### Overlay Color Legend

| State              | Color     | Shape     |
| ------------------ | --------- | --------- |
| `MOVE_REACHABLE`   | Black 25% | Dot       |
| `ACTION_REACHABLE` | Red 25%   | Dot       |
| `ATTACKABLE`       | Red 50%   | Highlight |
| `PLAYER_UNIT`      | Blue 50%  | Highlight |
| `ENEMY_UNIT`       | Red 50%   | Highlight |

`Overlay.add(coord, state)` / `Overlay.remove(coord, state)` / `Overlay.remove_all()`. Uses `static var instances: Dictionary[Vector2i, Overlay]`. Last-pushed state wins.

### Unit System — Detailed

**Registry** (`StageUnit`): `at: Dictionary[Vector2i, Unit]`. Methods: `spawn(scene, coord, team)`, `despawn(coord)`, `recompute_tiles()`.

**Unit** (`src/game/stage/units/unit.gd`): `team: Team`, `coord: Vector2i`. Discovers `Health`, `Movement`, `Actions` children by node name in `_ready()`. `die()` → emits `unit_died`, erases from `StageUnit.at`, `queue_free()`. `on_turn_end()` → restore movement, recompute tiles, reset action uses.

**Concrete units:**

- `pawn.tscn` — 100 HP, 3 movement points, 1 Katana action (`attack_power=50`)
- `base.tscn` — No HP, no movement, no actions (structural)

**Movement** (`src/game/stage/units/components/movement.gd`):

- `compute_reachable_tiles()` — BFS flood-fill, budget = `movement_points`, cost from `Constants.TILES[source_id]["movement_cost"]`
- `head_to(target)` — Dijkstra path, Tween animation 0.1s/tile, updates `unit.coord` + `StageUnit.at` on finish

**Action hierarchy:**  
`Action` → `AttackAction` (`attack_type`, `element`) → `Katana` (adjacent melee, 50 dmg, 1 use/turn).  
`action.perform(target)` → damage + `available_uses -= 1` + emit `action_performed`.  
`action.on_turn_end()` → restore `available_uses`.

### Story System — Detailed

`Story.load_story(StoryResource)` processes entries with `await`:

| Entry                  | Field                         | Behavior                                     |
| ---------------------- | ----------------------------- | -------------------------------------------- |
| `BackgroundStoryEntry` | `background: Texture2D`       | Sets background rect                         |
| `DialogueStoryEntry`   | `character`, `text`           | Streams 50ms/char; `await ui_accept_pressed` |
| `ChoiceStoryEntry`     | `choices: Array[StoryChoice]` | Renders buttons; `await choice_made(index)`  |
| `StageStoryEntry`      | `stage: StageResource`        | `change_state(STAGE)` → `Game.stage.start()` |

When `Config.config.debug_skip_story = true` (current default), Background/Dialogue/Choice entries are entirely skipped; only `StageStoryEntry` runs.

Mid-battle story: `Stage._spawn_wave()` checks `wave.hooks`; `StoryHook` entries instantiate a `Story` node onto the stage's `CanvasLayer` and `await` it.

### Place / Dating System — Detailed

`Place._ready()`:

1. Creates `Datable` for "Aiko" (currently hardcoded, not read from `SaveManager.current_save.datables`)
2. Instantiates `DatableSprite` (Area2D) at 67% viewport height, centered, 33.5% height scale
3. Fires `Notification.notify()` "Welcome" toast

Click `DatableSprite` → `Place.interact_datable(datable)` → hides nodes in `hide_on_interact`, instantiates `DatableInteract` (close-up at 25%×, 67%×, choice buttons: "Nevermind") → `uninteract_datable()` restores state.

`Datable`: `name`, `id`, `level`, `points`. Level-up threshold: `100 + level*100`. Illustrations: static `ILLUSTS` dict keyed by `id`; only `"aiko"` defined.

> **Known gap**: `Place` does not read from or write to the save file's datable dict yet.

| Field         | Type       | Default       |
| ------------- | ---------- | ------------- |
| `version`     | int        | 1             |
| `saved_at`    | String     | ISO datetime  |
| `day`         | int        | 0             |

Serialized via `to_dict()` / `from_dict()`. Migration block: `if version < 1:`.

### Data Resources (`data/`)

**Stages:**

- `intro.tres` — map=`intro.tscn`, spawns `base` (PLAYER) + 2 `pawn` enemies at (1,0)/(0,1), objective=`ObjectiveKillAllEnemies`
- `field_0.tres` — empty placeholder

**Objectives:**

- `ObjectiveKillAllEnemies` — complete when `StageUnit.at` has no ENEMY units
- `ObjectiveSurviveTurns` — complete when `current_turn >= target_turn`

**Hooks (polymorphic `HookEntry`):**

- `StageHook` — spawns a `StageWave`
- `StoryHook` — plays inline `Array[StoryEntry]`
- Attachable to: wave spawn events, objective completion events

**Tile Set** (`data/maps/stage_tile_set.tres`):  
`tile_shape=3` (pointy-top hex), `110×128` px. Sources: 0=hexagon, 2=dirt, 3=grass, 4=grass_dark, 5=grass_light.

### Key Signals

| Signal                                    | Source                  | Receiver                | Purpose                    |
| ----------------------------------------- | ----------------------- | ----------------------- | -------------------------- |
| `SigBus.toggle_pause_menu`                | Escape / backdrop click | `MainScene`             | Global pause toggle        |
| `StageUnit.unit_spawned(unit)`            | `StageUnit.spawn()`     | `StageObjective`        | Track unit for objectives  |
| `Unit.unit_died(unit)`                    | `Unit.die()`            | `StageObjective`        | Check objective completion |
| `StageObjective.all_objectives_completed` | `check_objectives()`    | `Stage`, `StageSummary` | End battle                 |
| `Action.action_performed`                 | `Katana.perform()`      | `ActionCard`            | Refresh UI uses count      |
| `Story.ui_accept_pressed`                 | `Story._input()`        | internal `await`        | Advance dialogue           |
| `Story.choice_made(index)`                | `ChoiceContainer`       | internal `await`        | Branch story               |
| `Viewport.size_changed`                   | Engine                  | `DatableSprite`         | Responsive scaling         |

### Coding Patterns

- **Component pattern**: `Health`, `Movement`, `Action` are child nodes; reference parent via `get_parent()` (or `get_parent().get_parent()` for actions inside `Actions` container)
- **Static registry**: `Overlay.instances` shared across all `Overlay` instances
- **`await` async flow**: story uses `await signal_name` — no coroutine managers needed
- **`Game.*` direct refs**: tight coupling by design for simplicity (`Game.stage.unit.at`, etc.)
- **`debug_skip_story = true`**: default dev shortcut — disable for full VN playback
